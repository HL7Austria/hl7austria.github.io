## Artifacts Summary

This page provides a list of the FHIR artifacts defined as part of this implementation guide.

### Structures: Resource Profiles 

These define constraints on FHIR resources for systems conforming to this implementation guide.

| | |
| :--- | :--- |
| [EU AI Act Model Card](StructureDefinition-eu-ai-model-card.md) | A DocumentReference profile representing technical documentation about an AI system, such as intended use, limitations, risk-related information, performance-related information, and model documentation. |
| [EU AI Consent and Processing Context](StructureDefinition-eu-ai-consent.md) | A Consent profile documenting patient-facing information, permission status, and opt-out preferences for AI-supported processing where applicable. |
| [EU AI Execution Audit Event](StructureDefinition-eu-ai-machine-execution-audit-event.md) | An AuditEvent profile documenting execution-related metadata of an AI-supported processing event to support retrospective reconstruction and auditability. |
| [EU AI Generated Observation](StructureDefinition-eu-ai-observation.md) | An Observation profile representing a clinical output generated by an AI system, including AI-related transparency metadata and links to the relevant patient, encounter, and AI system. |
| [EU AI Human Oversight Assessment](StructureDefinition-eu-ai-human-oversight.md) | An ArtifactAssessment profile documenting professional review of an AI-generated output, including whether the result was accepted, corrected, modified, or overridden. |
| [EU AI Patient Explanation Communication](StructureDefinition-eu-ai-patient-explanation.md) | A Communication profile documenting patient-facing information about the AI-supported workflow, including the role of the AI system and the related clinical review where applicable. |
| [EU AI Practitioner Role](StructureDefinition-eu-ai-practitionerrole.md) | A PractitionerRole profile representing the role, qualification context, specialty, and AI-related training information of the human reviewer involved in oversight of an AI-supported workflow. |
| [EU AI Provenance](StructureDefinition-eu-ai-provenance.md) | A Provenance profile linking an AI-generated output to the contributing AI system, source data, and relevant processing or governance context. |
| [EU AI Responsible Organization](StructureDefinition-eu-ai-organization.md) | An Organization profile representing an organization involved in manufacturing, providing, deploying, or operating an AI system, including relevant accountability and contact information. |
| [EU AI System Device](StructureDefinition-eu-ai-device.md) | A Device profile representing an AI system or software component, including system identification, versioning, intended purpose, and selected regulatory documentation metadata. |

### Structures: Extension Definitions 

These define constraints on FHIR data types for systems conforming to this implementation guide.

| | |
| :--- | :--- |
| [AI Clinical Validation Status](StructureDefinition-ai-clinical-validation-status.md) | Documents whether the AI system is clinically validated, not clinically validated, under validation, or only technically validated. |
| [AI Performance Metrics](StructureDefinition-ai-performance-metrics.md) | Captures quantitative metrics and bias disclosures. |
| [AI Privacy Metadata](StructureDefinition-ai-privacy-metadata.md) | GDPR and AI Act privacy parameters. Third country transfer flags and data retention policies at the model level. |
| [AI System Specific Training](StructureDefinition-ai-system-training-status.md) | Mandatory flag indicating whether the human actor has received specific training for the utilized AI tool. |
| [AI Training Data Metadata](StructureDefinition-ai-training-data.md) | Details regarding provenance, EHDS categories, and data quality. |
| [Automated Decision-Making Flag](StructureDefinition-automated-decision-flag.md) | Indicates whether the AI-generated output was used as part of a solely automated decision-making process within the meaning of GDPR Article 22. |
| [Case-Specific Indication](StructureDefinition-case-specific-indication.md) | The clinical reason why the AI was used for this specific patient. |
| [EHDS Data Permit](StructureDefinition-ehds-data-permit.md) | The unique ID of the Health Data Access Body permit (required if secondary use). |
| [EHDS Secondary Use Purpose](StructureDefinition-ehds-secondary-use-purpose.md) | Documents the permitted purpose for secondary use of electronic health data under the EHDS. |
| [EHDS Usage Category](StructureDefinition-ehds-usage-category.md) | Categorizes the data processing as Primary Care or Secondary Use according to the EHDS. |
| [EU AI Act Explanation Requested Flag](StructureDefinition-eu-ai-explanation-requested.md) | Flag indicating if the patient (data subject) explicitly requested a clear and meaningful explanation of the AI's role and the clinical decision. |
| [EU AI Act Log Integrity Signature](StructureDefinition-eu-ai-log-integrity.md) | Cryptographic signature or verification hash to ensure the integrity, accountability, and non-repudiation of the AI execution audit log. |
| [Model Card Reference](StructureDefinition-ext-model-card.md) | A reference to the DocumentReference resource that acts as the Model Card, containing detailed documentation, intended purpose, and risk assessments. |
| [Patient AI Info Provided Flag](StructureDefinition-patient-ai-info-provided.md) | Confirmation that the patient was informed about the use of AI systems according to AI Act transparency rules. |
| [Third-Country Data Transfer](StructureDefinition-third-country-data-transfer.md) | Captures if patient data is transferred outside the EU by this device. |

### Terminology: Value Sets 

These define sets of codes used by systems conforming to this implementation guide.

| | |
| :--- | :--- |
| [AI Clinical Validation Status ValueSet](ValueSet-eu-ai-clinical-validation-status-vs.md) | Codes describing the clinical validation status of an AI system. |
| [AI Data Quality ValueSet](ValueSet-eu-ai-data-quality-vs.md) | Codes describing data-quality characteristics relevant for training-data documentation (Art. 10 AI Act). |
| [AI Performance Metric ValueSet](ValueSet-eu-ai-performance-metric-vs.md) | Codes for technical quality and performance metrics (QUAL-01). |
| [EHDS Data Category ValueSet](ValueSet-ehds-data-category-vs.md) | Categories of electronic health data relevant for secondary-use documentation under the EHDS (EHDS Art. 51). |
| [EHDS Secondary Use Purpose ValueSet](ValueSet-ehds-secondary-use-purpose-vs.md) | Permitted purposes for secondary use of electronic health data under the EHDS. |
| [EHDS Usage Category ValueSet](ValueSet-ehds-usage-category-vs.md) | Codes defining whether data usage is documented as primary use or secondary use (LAW-03.1). |
| [EU AI Case-Specific Indication ValueSet](ValueSet-eu-case-specific-indication-vs.md) | Clinical and administrative reasons for applying an AI system in a specific case (USE-04). |
| [GDPR Article 6 Legal Basis ValueSet](ValueSet-gdpr-art6-legal-basis-vs.md) | Value set including GDPR Article 6 legal bases relevant for documenting the lawful processing of personal data. |
| [GDPR Article 9 Exception ValueSet](ValueSet-gdpr-art9-exception-vs.md) | Value set including GDPR Article 9 exceptions relevant for documenting the processing of special categories of personal data, including health data. |
| [Human Intervention Type ValueSet](ValueSet-eu-ai-intervention-vs.md) | Codes representing the type of human oversight or intervention (HL-03.1). |
